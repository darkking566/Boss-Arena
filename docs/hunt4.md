# 狩獵模式（4v1）總設計案

> 2026-11-02 起的深化計畫見本文件末尾；目前活動階段與驗證狀態以根目錄 `NEXT.md` 為準。

> 狀態：已確認（2026-11-01）。**P1 骨架、P2 共通系統、P3 四把近戰、P4 獵人大腦、P5 裝備深度、P6 第二批武器（大錘 / 狩獵笛 / 長槍 / 銃槍）、P7 第三批（斬擊斧 / 充能斧 / 操蟲棍）、P8 第四批（弓 / 輕弩 / 重弩）完成**，十四種武器全部可用；隊伍平衡也做過一輪（§9.8）。
> 已定案（2026-11-01）：跨場持久學習、固定四位獵人（本文件設計，可改）、新的獨立模式、第一版 = 骨架 + 共通系統 + 4 種近戰武器。

## 1. 一句話
四位個性鮮明的 AI 獵人組隊討伐一位 Boss，玩家觀戰；獵人用魔物獵人式武器作戰，每場結束都會把經驗寫進「武器熟練表」與「Boss 圖鑑」，越打越會打。

機制靈感來自《魔物獵人：荒野》的武器系統；名稱、數值、招式細節都用本作自己的，不照搬原作內容與美術。

## 2. 沿用的現有架構（不重造）
| 現有 | 本模式怎麼用 |
|---|---|
| `World([defs],[defs])` 團隊戰（`teamMode`、`retarget`、`foes`） | `new BD.World([h1,h2,h3,h4], [boss], { hunt4: … })`，Boss 目標改由仇恨值決定 |
| 獵魂 `buildHero` / hero 定義 / `def.hero` 略過二階段 | 每位獵人是一個 hero 定義，由 `BD.Hunt4.buildHunter(hunter, save)` 產生 |
| 獵魂太刀 `LOGIC.katana`、`deflect` 特性、`BD.agentize` | 太刀直接搬成第一把武器；武器邏輯表改成共用（獵魂之後也能用新武器） |
| `AIController` + `OpponentModel` 讀習慣 + 智慧閃避 | 獵人大腦包在外層，底層移動 / 閃避沿用 |
| 狀態系統（中毒、易傷、硬直…）、架勢 | 異常狀態累積、倒地 / 暈眩直接接上 |
| `BD.vrng()`、指紋測試 | 本模式只在 `opts.hunt4` 下啟用，1v1 / 3v3 / 獵魂指紋必須不變 |

## 3. 戰場規則
- **勝利**：Boss 死亡。**失敗**：全隊共用 3 次「力竭」（倒下後 8 秒在場邊復活，扣 1 次），或超過時限（遊戲時間 15 分）。
- **Boss 強化**：生命依人數放大（初值 ×3.2，模擬調校），架勢 / 部位耐久同步放大；Boss 本體招式不改。
- **仇恨值**：傷害、正面站位、剛打出大怯 / 倒地的人仇恨上升，隨時間衰減；Boss 每隔一段時間依仇恨換目標，偶爾隨機換人（避免一直追同一人）。
- **觀戰 HUD**：四人頭像（血 / 耐力 / 武器量表 / 力竭次數）、Boss 部位圖（傷口 / 破壞）、事件跑馬燈（「凜 見切成功」「茉莉 真蓄力命中頭部 2,140」）、F6 顯示每位獵人當下的判斷與學習值。

## 4. 共通戰鬥系統（荒野式，第一版全做）
1. **部位與肉質**：每位 Boss 自動切出 頭 / 身體 / 前腳 / 後腳 / 尾 五個部位（依命中角度與距離判定），各有斬 / 打 / 彈的吸收率與破壞耐久。預設由體型 / 原型自動產生，可在 `js/data/hunt4/parts.js` 逐 Boss 覆寫。部位破壞給額外素材。
2. **傷口與集中弱點攻擊**：部位累積傷害後開「傷口」（紅色標記）；每把武器都有一招「集中弱點攻擊」，打中傷口 → 傷口破裂、大傷害、必定怯。傷口破裂對應部位進入「疤痕」，短時間不再開。
3. **集中模式**：AI 進入集中時可朝傷口方向出招（對 AI 而言 = 出招方向自動對準最近傷口、看得到部位資訊）。
4. **銳利度**：近戰武器有顏色段（紅→紫），命中扣銳利，越鈍傷害越低、低段打硬肉會被彈開；「磨刀」要停下 2 秒（AI 判斷何時安全）。
5. **相殺 / 力量對抗 / 完美防禦**：特定招式（各武器指定）在出招瞬間吃到攻擊 → 相殺：互相抵銷並讓 Boss 大硬直；大招對撞時可能進入力量對抗（雙方連打比拚，AI 依熟練度決定贏面）；盾類武器有完美防禦（精準時機格擋 → 無傷 + 反擊窗）。
6. **怯 / 倒地 / 暈眩 / 疲勞**：部位累積 → 怯；架勢崩 → 倒地（全隊輸出窗）；打擊類打頭累積暈眩；Boss 長時間戰鬥進入疲勞（招式變慢、會撲空）。**控制後先出一招**：Boss 被控中、或剛恢復還沒打出下一招（過了前搖）前，新的怯 / 暈眩 / 倒地 / 麻痺 / 睡眠 / 相殺硬直都先記下一筆（時間長的優先），出完那一招才補上；閃光彈在這段期間不丟。命中停頓 / 凍結只在 Boss 打中獵人時觸發，戰鬥中不放慢動作（勝負那一下除外）。
7. **屬性與異常**：武器屬性（火 / 水 / 雷 / 冰 / 龍）乘上部位屬性弱點；異常（毒、麻痺、睡眠、爆破）累積值滿就觸發，每次觸發後耐性上升。
8. **雙武器**：每位獵人帶主 / 副兩把武器，戰鬥中可切換（需收刀 1 秒）；AI 依情境切換（例如 Boss 飛起來 → 換遠程）。
9. **道具**：回復藥、磨刀石、閃光彈、生命粉塵（群體回血）。數量依角色與裝備。

## 5. 十四種武器（分批）
每把武器 = 一組招式資料（`js/data/hunt4/weapons/<id>.js`）+ 一份武器邏輯（量表、連段分支、特殊狀態，`js/engine/hunt4/weapons/<id>.js`）+ 專屬集中弱點攻擊。

|---|---|---|
| **第一版** | 太刀 | 氣刃槽 / 練氣等級、見切、居合、登龍（下刺）、彈刀 |
| | 大劍 | 蓄力 I~III、強蓄力 / 真蓄力、鐵壁衝撞（受擊減傷不倒）、相殺斬 |
| | 雙刀 | 鬼人化（持續耗耐力）、鬼人槽、鬼人亂舞、鬼人迴避 |
| | 片手劍 | 盾擊 / 打擊暈眩、完美防禦、跳躍斬、完美突進、拔刀時可用道具 |
| 第二批 | 大錘、狩獵笛、長槍、銃槍 | 蓄力打擊 / 暈眩；旋律增益與響玉；鐵壁防禦反擊；砲擊與龍擊砲 |
| 第三批 | 斬擊斧、充能斧、操蟲棍 | 變形與屬性解放；充能瓶 / 屬性強化；獵蟲採集三色精華與空中戰 |

## 7. 獵人大腦與學習
三層，越上層越「像人」：
1. **身體（沿用）**：移動、智慧閃避、`agentize` 的時機抖動。抖動大小 = 熟練度的函數（新手 ±0.12 秒 → 熟練 ±0.03 秒）。
2. **武器策略**：把情境分桶（距離段 × Boss 狀態〔出招中 / 硬直 / 倒地〕× 自己資源〔量表、耐力〕× 是否有傷口），每桶對每個選項（某招 / 某連段 / 等待 / 閃避 / 磨刀）記一個平均回報。回報 = 造成傷害 − 受到傷害 × 個性權重 + 怯 / 傷口破裂獎勵 − 空振懲罰。選擇時加上個性偏好與逐漸變小的探索率。
3. **Boss 圖鑑**：每位獵人對每位 Boss、每一招記錄：預警到命中的時間、哪個閃避方向成功率最高、招後硬直多長、哪個部位最軟、Boss 偏好打誰。戰鬥中查表決定閃避時機與懲罰窗；圖鑑完成度顯示在選單。

- **持久化**：`localStorage['bd.hunt4.save']`，每人一份熟練表 + 圖鑑，數值有上限（只存統計量，不存原始紀錄）。可匯出 / 匯入 / 重置。
- **可重現**：戰鬥內的探索亂數用 `(save 版本, 種子)` 決定，同一份存檔 + 同一種子結果一樣，方便測試。
- **無頭訓練**：`node test/hunt4_train.js <boss> <場數>`，輸出每 N 場的勝率 / 平均時間 / 力竭數 / 見切成功率曲線，**驗收標準是曲線要上升**。

## 8. 裝備深度化（第四階段，先定方向）
目標：每件裝備都改變「怎麼打」，而不只是加數字。
- **素材**：每場依擊殺與部位破壞掉落 Boss 素材（鱗 / 角 / 尾 / 寶玉，寶玉稀有）。
- **武器**：每位 Boss 一條武器樹，帶該 Boss 的特色。除了攻擊 / 屬性 / 銳利度，每把有 1 個**武器特性**，例：
  - 雷神索爾系「連鎖雷」：集中弱點攻擊命中後，雷電跳到其他傷口。
  - 恐暴龍系「暴食」：傷口破裂時回復生命，但銳利度消耗加倍。
  - 小次郎系「燕返」：見切 / 相殺成功後下一招自動追加一段斬擊。
- **防具技能**（有等級，可疊）：偏向行為改變型，例：看破（連續命中提高會心）、攻擊守勢（完美防禦後攻擊上升）、挑戰者（Boss 憤怒時更強）、迴避距離、耐震、逆境（力竭過後變強）、收刀術。
- **Boss 套裝效果**：穿滿改變打法，例：宙斯套「超越時間」——完美迴避讓周圍時間變慢 1 秒；亞當套「神虛視」——見切成功會複製該招的一小段。
- **AI 會配裝**：每位獵人依個性挑偏好技能，學習時把裝備納入情境（同一招在有「攻擊守勢」時評價更高）。

## 9.1 P2 實作備忘（2026-11-01）
- 數值都在 `js/data/hunt4/parts.js`；管線在 `js/engine/hunt4/combat.js`，由 `mode.js` 包住 `w.damageBoss`（只攔獵人打 Boss；追加傷害走原始函式，不重複累積）。
- 部位由攻擊者在 Boss 面向的哪一側決定（頭 / 腳 / 身 / 尾），沒有真正的碰撞部位；集中弱點攻擊打到哪都會打破最近的傷口（代表集中模式的瞄準）。
- Boss 不再被單一重擊打倒（永久起身保護），只有架勢崩潰才倒地；倒地後架勢上限 ×1.5。
- 獵人的屬性 / 異常（凜 雷、茉莉 爆破、小柚 毒、瑟琳娜 麻痺）是 P5 裝備上線前的暫時設定。
- 副武器只帶已實作的（凜 弓、小柚 輕弩，用的是獵魂的舊版簡易武器）；茉莉的大錘、瑟琳娜的狩獵笛要等 P6。
- 平衡（46 場模擬）：獵人勝 67%、平均 2 分 20 秒、Boss 被控約 24% 時間、每場怯約 10 次 / 倒地約 4 次 / 傷口破壞約 6 次。

## 9.2 P3 實作備忘（2026-11-01）
- 四人主武器：凜 太刀、茉莉 大劍、小柚 雙刀、瑟琳娜 片手劍。武器資料 `js/data/hunt4/weapons.js`，驅動 `js/engine/hunt4/weapons.js`。
- 驅動 = choose（包住 AI 的 chooseSkill，決定出哪招）+ next（招式結束時接下一招：連段 / 蓄力段數 / 鬼人系）+ react（攻擊將至時的反應招：太刀彈刀、大劍連段中衝撞、片手劍舉盾）+ tick + gauge（HUD 量表）。
- 太刀補上「氣刃兜割」（紅刃才能放，命中後回到白刃）；大劍 蓄力 → 強蓄力 → 真蓄力，鐵壁衝撞減傷 50% 且開頭 0.3 秒可相殺；雙刀 鬼人化耗體力、鬼人槽、鬼人強化、鬼人亂舞、鬼人迴避（翻滾省體力）；片手劍 連斬 / 盾擊（打擊）/ 完美突進 / 跳躍斬 / 防禦（前 0.2 秒完美防禦 → 立刻反擊）/ 拔刀喝藥較快。
- 相殺、力量對抗（Boss 單擊 ≥120 時）、防禦、鐵壁都是招式旗標，由 `h4arms` 特性處理。
- 平衡（46 場模擬，Boss 生命 ×9.5）：勝率 61%、平均約 1 分 40 秒、每秒輸出 太刀 77 / 大劍 55 / 雙刀 100 / 片手劍 70；小柚最常力竭（每場 0.74 次），符合人設。
- 已知：大劍的蓄力斬約一半揮空（Boss 移動）——留給 P4 學習「什麼時候蓄得完」。

## 9.3 P4 實作備忘（2026-11-01）
- 全部在 `js/engine/hunt4/brain.js`（學習存檔結構與防呆也在這裡，沒有另開 memory.js）；localStorage 讀寫在 `main.js`（`bd.hunt4.save`），選單可匯出 / 匯入 / 重置。
- 三張學習表，都是「選項 × 平均回報」，次數上限 200（舊經驗會慢慢被新經驗蓋過），只存統計量：
  - **武器策略** `strat[武器][距離段|低血?|Boss 狀態]` → 出手 / 退開等待。AI 想出招時查表（包在 `H4Weapons.equip` 的 chooseSkill 外層）。回報 = 2.5 秒內（造成傷害 − 承受傷害 × 個性權重）/ 300，期間力竭 −3。個性權重 = 0.6 + 1.2×謹慎 + 0.6×(1−冒險)。先驗：冒險 / 愛表現的人偏向出手，耐心的人在 Boss 出招中偏向等。
  - **Boss 圖鑑** `dex[Boss].sk[招式]`：`lead` 反應招提早多少秒按（0.2 / 0.1 / 0.04），`dir` 翻滾方向（照 AI 原方向 / 偏左 / 偏右 63°）；0.8 秒內沒被打中（≤2% 生命）算成功。另記部位實際倍率（最軟部位）、被 Boss 追的時間比例、戰績。
  - **熟練度** = 1 − e^(−場數 × (0.5 + 學習力) / 150)。反應抖動 ±0.12 秒（新手）→ ±0.03 秒，由 0.6×熟練 + 0.4×對這招的熟悉度決定；探索率 0.3 → 0.08。
- 探索亂數獨立於戰鬥亂數，種子 = (戰鬥種子, 存檔場數)：同存檔 + 同種子結果相同（有測試）。沒給存檔的對局 = 全新獵人。
- 選單顯示每人各武器熟練度、對所選 Boss 的圖鑑（摸熟招數 / 全部、最軟部位、被追比例、戰績）；結算表加「反應 / 翻滾成功」與熟練度；F6 在獵人頭上顯示大腦最近一次的決定。

## 9.8 隊伍平衡（2026-11-01）
- 量法：5 種隊伍 × 23 位 Boss × 2 種子，全新存檔、無裝備。輸的原因幾乎都是力竭 3 次，所以重點看平均力竭次數。
- 找到的原因：
  - 強隊強在**狩獵笛的回復**。預設隊只把茉莉換成狩獵笛，勝率就從 50% 跳到 72%，力竭從 2.0 次降到 1.4 次。換成大錘只有 50%。
  - 遠程隊強在幾乎不受傷。
  - 各隊被打的時間點大多是「沒在出招」的時候（閃避失敗），不是某一招特別危險。
- 調整：
  - 狩獵笛：回復旋律 15% → 5%，全音 8% → 3%，防禦強化 ×0.85 → ×0.9。
  - 遠程防具較薄：弓 / 輕弩 / 重弩受傷 ×1.3（武器規格 `taken`，在 `h4arms` 的受傷攔截裡套用）。
  - 長槍：防禦承受比例 12% → 18%。
  - 第三批的生存：零距離解放突擊、大解放斬受擊減傷 30%（鐵壁，不被打斷）；橙精華受傷 ×0.9 → ×0.8；斬擊斧屬性解放 ×1.2 → ×1.25。這幾項影響很小，在誤差內。
- 結果（勝率）：

  | 隊伍 | 調整前 | 調整後 |
  |---|---|---|
  | 預設隊 | 54% | 50% |
  | 預設隊（茉莉換狩獵笛） | 72% | 61% |
  | 大錘 / 狩獵笛 / 長槍 / 銃槍 | 87% | 70% |
  | 第三批隊 A | 43% | 41% |
  | 第三批隊 B | 39% | 46% |
  | 遠程隊 | 83% | 61% |

  全距從 39~87% 縮到 41~70%。同樣配置重跑會差個幾 %，以上都是單次量測。
- 沒做：第三批隊還在 40% 出頭。原因是沒有輔助武器、近身又不會防禦，這比較像組隊取捨，就沒有再硬拉。有裝備和學習之後，勝率整體會往上（P5 量過約 75%）。

### 12.3 深化階段 1：戰後成長回顧（首個可試用成果）

入口：選單「狩獵」→ 出發 → 任一勝利或失敗結算。
核心操作：玩家看完一場，在結算中查看四人的本場表現與成長，再重賽或回選單。
狀態來源：`H4Brain` 的既有熟練度 / 圖鑑、`h.brain.res` 與本場統計。開戰前快照與結算回顧只留在本場，不寫入持久存檔。

工作清單：
- [x] 開戰時取得各人可使用主副武器的熟練度與本 Boss 圖鑑快照。
- [x] 結算時記錄實際使用武器的前後熟練度、經驗增量與圖鑑前後變化。
- [x] 呈現反應 / 翻滾的成功與嘗試數，並說明既有判定：觀察期間受到超過最大生命 2% 的傷害算失敗；不是逐招完全閃避率。
- [x] 嘗試數為零顯示尚無紀錄；樣本少時提示不足以判斷穩定程度。圖鑑既有門檻不等於保證掌握招式。
- [x] 勝利與失敗均接入回顧；保留原有詳細統計、素材與製作資訊。使用者已試玩回覆正常，未明確指出的細項仍保留驗證缺口。
- [x] 舊存檔、不同武器、換副武器、重賽資料隔離的自動檢查。
- [ ] 瀏覽器結算、其他模式切換與窄視窗檢查；本機連線 / 開檔受工具限制，見 `NEXT.md`。

允許修改：本文件 / NEXT、狩獵大腦的只讀快照與結算摘要、主程式結算、必要 HTML / CSS 與針對性測試。

### 12.4 深化階段 2：團隊配合（後續）

前提：階段 1 試玩後確認繼續，另行凍結行為與評估門檻。
第一小步為「傷口合作」：有人造出傷口後，其他獵人依距離、危險、血量與武器能力，提高利用傷口的優先度。使用者已回覆回顧正常，並授權開始這一小步。
第二小步才是「危急支援」：沿用粉塵與閃光掩護，改善隊友低血 / 被追時的支援判斷。
不得強制協作或無限救援，仍受個性、資源、距離與眼前危險限制。

交付：合作觸發、拒絕 / 中止條件、實際結果與可辨認的提示 / 戰後記錄。
驗收：固定條件重現成功 / 不適用 / 失敗；不卡住、不頻繁換目標、不無視危險。
比較同存檔與固定種子的勝率、力竭與耗時；門檻依當時基準訂定，不預先虛構改善幅度。
保護蓄力等意圖辨識先暫存，確認引擎能可靠觀測後再議。

#### 2.1 傷口合作：本次執行範圍

輸入：目前傷口 / 集中攻擊、四人個性、威脅掃描、已通過試玩的成長回顧。
輸出：記錄造傷者、可用隊友更積極接應、每處傷口同時一位合作接應者、實際結果與結算統計。

- 造傷者按跨過傷口門檻的最後一擊記名；不是整段傷害貢獻排名。
- 只在獵人可以自由行動時評估，不追逐遠方傷口，不搶斷既有連段、防禦或閃避。
- 血量與體力不足、冷卻 / 彈藥不足、眼前有威脅或 Boss 轉階段時，不安排接應。
- 使用武器本來的集中攻擊，個性影響接應意願；每處傷口短暫預留，避免多位隊友同時合作攻擊同一目標。
- 合作攻擊只認當時選定的那一處傷口；傷口消失、過期、獵人倒下或招式中斷時釋放預留，不把舊投射物誤算成下一處傷口的合作。
- 戰鬥紀錄顯示出手與成功配對，回顧顯示製造 / 助攻 / 合作出手與成功、未命中、中止。統計只留本場，不改持久學習格式。
- 允許本次 4v1 行為改變；不改其他模式、傷口傷害 / 壽命 / 獎勵、學習回報或掉落，不重新產生正式指紋。
- 驗證：觸發 / 拒絕 / 釋放 / 中斷 / 投射物 / 多人競爭的固定測試；完整測試與兩種指紋。
- 同條件調校：23 位 Boss × 種子 7 / 17，比較新獵人與僅主副武器 xp=150（無裝備、無策略訓練）的兩組 fixture，各 46 場。勝率差超過 15 個百分點、平均耗時變動超過 20%、平均力竭差超過 0.5 時先調查原因；這是異常檢查門檻，不是承諾提升幅度。
- 退出：自動證據完成後交使用者觀察一場並驗收；工具的瀏覽器限制仍如實保留。驗收前不進危急支援或階段 3。

實作回執：安全判斷與預留在 `js/engine/hunt4/mode.js`，指定傷口命中在 `combat.js`；合作招式只複製本次時間軸，不污染共享武器定義。箭的合作標記沿既有 `extra` 傳遞，已結算 / 過期標記不會打破下一代傷口。統計只留本場，正式指紋與存檔版本均未修改。測試與使用者驗收狀態見 `NEXT.md`。

#### 2.2 危急支援：生命粉塵與閃光掩護

使用者已接受傷口合作，並明確要求兩種支援一起做。本次範圍固定為現有道具的安全時機、避免重複消耗與實際結果記錄。

- 粉塵：附近一位隊友極低血，或低血且面臨即將到來的攻擊，或多人同時受傷時，依照顧個性決定救援。檢查使用者的安全、範圍與庫存；不強制中斷出招 / 翻滾 / 防禦。
- 保留目前瞬間施效、使用後硬直的道具規則，以及回血比例 / 庫存。實際回復量按生命上限截斷；只有回復量大於零的活人計為受益者。包含自己時清楚說明，累計按人次計。
- 閃光：保留工作區既有 `H4.ITEMS.flashAt = 0.25`；隊友低於此門檻且被 Boss 正在施展的攻擊鎖定時，安全且在距離內的獵人才考慮掩護。
- 不在 Boss 倒地 / 暈眩 / 轉階段 / 收招時追加閃光；耐性令剩餘控場時間太短時不浪費。兩種道具有各自的隊伍短間隔，避免同時連丟。
- 閃光記錄實際打斷的招式，以及受掩護隊友在接下來 2 秒內「未力竭 / 力竭 / 戰鬥提早結束」的觀察結果；不推論阻擋了多少傷害、不宣稱必然救命。
- 回顧新增兩種道具的有效貢獻，戰鬥紀錄可看救援對象；僅保存本場統計，舊存檔繼續使用。
- 修改邊界：狩獵 mode / brain / main、必要的道具設定、測試與現有文檔。只改 4v1，不改其他模式、學習回報、掉落、裝備與正式指紋基準。
- 驗證：危急 / 多人 / 零效益 / 範圍 / 死亡 / 庫存 / 威脅 / 既有控制 / 耐性 / 重複消耗 / 掩護觀察結算的固定測試；完整測試與兩種指紋。
- 調校沿用兩組各 46 場（全新與 xp=150、無裝備 / 無策略訓練），以目前包含 25% 閃光門檻的工作區作基準。並行戰鬥改動後，以同來源雜湊的舊支援測試替身 / 新支援作公平比較。超過勝率差 15 個百分點、耗時差 20%、力竭差 0.5 時先調查。
- 下一道門：兩項自動檢查與調校完成後，交使用者試玩；不自動進入部位戰術。

### 12.5 深化階段 3：部位戰術（後續）

前提：合作行為驗收，確認目前角度式部位判定可支撐選定效果。
先選 1～2 位 Boss、各一個易辨認部位，試作破壞後某個招式的收招 / 範圍改變。
破壞提示、戰後效果說明與實際行為要一致；未破壞時不提前生效。
不一次套用所有 Boss；人形、巨獸與騎乘角色按個別合理性設計。
驗收：破壞前後招式差異可重現、效果有取捨且玩家看得懂，其他模式行為不受影響。
完整部位碰撞重做不在首批範圍。

### 12.6 深化階段 4：裝備與準備（後續）

前提：前階段戰術需求明確，另定存檔相容方案。
依序實作：
1. 戰前說明自動配裝的可證實理由：屬性、個性、技能 / 套裝或戰績因素。
2. 個別獵人的「原本個性 / 生存 / 輸出 / 支援」傾向，AI 從已擁有裝備選擇。
3. 少量 Boss 裝備的防守反擊 / 高風險輸出分支，並評估多餘素材的合理用途。

驗收：傾向在有裝備可選時確實影響選擇，缺裝也能正常出戰；原本個性是新增設定的預設行為。
理由必須對應真正評分，不捏造 AI 意圖。完整手動配裝尚未採用。

### 12.7 深化階段 5：多樣任務（後續）

前提：部位與準備系統穩定，確認獎勵與存檔責任。
先做「部位調查」和「生存挑戰」，各自訂出成功、失敗與領獎時點。
入口需顯示目標 / 獎勵，戰鬥能查進度，結算能說明結果。
普通狩獵繼續可用；獎勵與任務目標相關，不重複發放、不在失敗時錯發。
驗收：成功 / 失敗 / 重賽判定可重現、舊存檔可用、玩家不讀程式也看得懂要求。
限時與招式研究任務暫存，第一批驗收後才再議。
